# 프롬프트 버전 관리

프롬프트는 **코드와 같이 버전을 매긴다.** 바꾸면 파일을 새로 만들고, 이전 것을 지우지 않는다.
회귀 테스트가 어느 버전에서 무엇이 깨졌는지 추적할 수 있어야 한다.

| 파일 | 상태 | 비고 |
|---|---|---|
| `sql-where.v1.txt.b-scope-deprecated` | **폐기** | B안(WHERE 조각만 생성) 기준. 2026-09-02 C안 채택으로 폐기 |
| `sql-select.v1.txt` | **사용 중** | C안. SELECT 문 전체를 생성한다 |
| `intent-classify.v1.txt` | 미착수 | 의도 분류 |

## B안을 폐기한 이유

B안(WHERE 조건만 LLM 이 생성)은 검증 표면이 좁아 안전하지만,
**검증할 SQL 자체가 없어져 프로젝트 주제가 사라진다.**
`nl-query-guard` 인데 guard 할 대상이 없어진다. ADR-001 참조.

## 규칙 3번이 방어층 3과 짝을 이룬다

```
프롬프트: user_id 조건을 절대 넣지 않는다
Enforcer: user_id 가 있으면 거부하고 재생성 신호를 보낸다
```

**프롬프트는 계약이고, Enforcer 는 그 계약을 강제하는 쪽이다.**
프롬프트만 믿지 않는다. LLM 은 지시를 어길 수 있다.
