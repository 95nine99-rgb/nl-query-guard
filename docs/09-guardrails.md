# 가드레일 — 사람이 아니라 시스템이 막는다

이 프로젝트의 주제는 **"AI 출력을 백엔드가 검증한다"** 이다.
같은 원칙을 개발 과정에도 적용했다. **확인은 사람이 하지 않는다. 막는 건 전부 자동이다.**

## 가드 4개

| # | 무엇을 막나 | 무엇이 막나 | 언제 |
|---|---|---|---|
| 1 | LLM이 만든 위험한 SQL | JSQLParser + 화이트리스트 (`SqlValidator`) | 런타임 |
| 2 | 파서를 뚫은 SQL | 읽기 전용 DB 계정 + row limit + 타임아웃 | 런타임 |
| 3 | **비밀 정보 커밋** | **`.githooks/pre-commit`** | 커밋 직전 |
| 4 | 프롬프트 정확도 하락 | GitHub Actions 회귀 테스트 | PR 머지 직전 |

**4개 다 "내가 조심한다" 가 아니라 "조심하지 않아도 막힌다" 로 되어 있다.**
사람의 주의력은 반복에서 무너진다. 그래서 주의력에 기대지 않는다.

## 3. 비밀 정보 커밋 차단

### 왜 필요했나

이 리포는 public 이다. 그리고 **2026-08-28 에 LLM API 키가 들어온다.**
`.gitignore` 만 믿으면 실수 한 번에 키가 영구히 히스토리에 남는다.
공개 리포에 올라간 키는 바로 스캐닝 봇에게 수집된다. 지운다고 사라지지 않는다.

### 어떻게 막나

`.githooks/pre-commit` 이 스테이징된 파일만 검사한다.

| 검사 | 패턴 |
|---|---|
| 파일 확장자 | `.env*` `*.pem` `*.key` `*.p12` `*.jks` `*.keystore` |
| LLM 키 | `sk-...` `sk-ant-...` |
| GitHub 토큰 | `gh[pousr]_...` |
| AWS 액세스 키 | `AKIA[0-9A-Z]{16}` |
| 개인키 | `BEGIN ... PRIVATE KEY` |
| 하드코딩된 시크릿 | `api_key|secret|token = <24자 이상>` |

하나라도 걸리면 **커밋이 거부된다.**

### 통과시키는 것 — 그리고 그 이유

로컬 `docker compose` 전용 더미 비밀번호(`apppw` `rootpw` `ropw`)는 **일부러 통과시킨다.**

이걸 막으면 `docker compose up` 한 줄 재현이 깨진다.
그건 이 프로젝트의 완료 정의 중 하나다. **재현 가능성과 보안이 충돌하는 지점이고, 여기서는 재현을 택했다.**
대신 `application.properties` 에 "로컬 전용 더미" 라고 명시해 뒀다.

> 가드레일은 **무엇을 막느냐** 만큼 **무엇을 일부러 통과시키느냐** 가 설계다.
> 전부 막으면 아무도 안 쓰게 되고, 안 쓰는 가드는 없는 것과 같다.

### 왜 `.git/hooks` 가 아니라 `.githooks` 인가

`.git/hooks` 는 **버전관리가 안 된다.** 내 컴퓨터에만 있고 클론하면 사라진다.
`.githooks` 에 두면 리포에 같이 올라가서 남도 쓸 수 있다.

활성화는 리포마다 1회:

```bash
git config core.hooksPath .githooks
```

**클론해도 자동 적용되지 않는다.** git 이 임의 스크립트를 자동 실행하지 않게 막아둔 것이라 이건 의도된 동작이다.
그래서 README 실행법에 이 줄을 넣어야 한다.

### 한계 (알고 있다)

- `git commit --no-verify` 로 우회된다. **로컬 훅은 마지막 방어선이 아니라 첫 번째 방어선이다**
- 이미 히스토리에 들어간 비밀은 못 잡는다. 그건 `git filter-repo` + 키 폐기가 답이다
- 정규식 기반이라 새로운 형태의 키는 놓친다

**진짜 방어선은 GitHub Push Protection 이다.** 서버 쪽에서 막으므로 우회가 안 된다.
Settings → Code security 에서 켤 수 있고, 훅과 같이 쓰는 게 맞다.

> 방어를 한 겹에 걸지 않는다. 이건 `SqlValidator` 를 4겹으로 만든 것과 같은 판단이다.
