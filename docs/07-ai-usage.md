# AI 사용 기록 · 툴체인 결정

이 프로젝트의 주제는 "AI 출력을 백엔드가 검증한다"이다.
개발 과정에도 같은 원칙을 적용한다. **AI가 코드를 빨리 짜주는 건 전제이고, 무엇을 짜라고 지시할지가 실력이다.**

---

## 1. 원칙

| | 예시 |
|---|---|
| 하지 않는다 | "Text2SQL 검증 레이어 만들어줘" — 무엇을 만들지 내가 모르는 상태 |
| 한다 | "SELECT only + 허용 테이블 화이트리스트로 검증하는 Validator를 만들어줘. 인터페이스는 `validate(String sql) → ValidationResult`" — **설계는 내가, 타이핑은 AI** |
| 한다 | "내가 짠 이 파서가 뚫릴 케이스 5개를 공격자 입장에서 만들어봐" |
| 한다 | "이 두 방식의 트레이드오프를 표로 정리해줘. 결정은 내가 한다" |

**핵심**: AI에게 넘기는 건 구현이고, 절대 안 넘기는 건 **판단**이다.
무엇을 통과시킬지 · 임계값을 얼마로 할지 · 어느 방어층을 몇 겹 둘지.

---

## 2. MCP 툴체인 — 무엇을 붙였고 무엇을 안 붙였나

> **MCP를 많이 붙이는 게 실력이 아니다.** 붙일수록 컨텍스트가 오염되고 느려지며,
> 쓰기 권한이 있는 서버는 사고를 낸다. **왜 이걸 붙였고 무엇을 뺐는지**가 판단이다.
> 이 표 자체가 포트폴리오 증거가 된다.

### 붙인 것

| MCP | 언제 붙였나 | 왜 | 권한 |
|---|---|---|---|
| Context7 | | Spring Boot 4.x · JSQLParser 최신 API 환각 방지. 버전별 실제 문서를 프롬프트에 넣어줌 | 읽기 |
| GitHub | | PR 생성·리뷰·워크플로 확인. 혼자 PR을 도는 구조라 손이 많이 감 | 최소 스코프 |
| MySQL (읽기 전용) | | 스키마·실행계획 확인. **반드시 `query_ro` 계정으로 붙인다** | **읽기 전용** |
| Playwright | | 데모 GIF 촬영, E2E 확인 | 로컬 |

### 안 붙인 것과 이유

| MCP | 왜 뺐나 |
|---|---|
| MySQL 쓰기 권한 | 이 프로젝트의 주제가 "권한 경계"인데 내 툴체인이 그걸 어기면 앞뒤가 안 맞는다 |
| | |

### 판단 기록

> 붙일 때마다 여기에 한 줄. "무엇 때문에 필요해졌는지"를 남긴다.
> 필요해지기 전에 미리 붙이지 않는다.
