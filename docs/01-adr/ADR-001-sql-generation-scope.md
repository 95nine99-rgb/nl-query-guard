# ADR-001 · LLM에게 SQL을 어디까지 만들게 할 것인가

- 상태: 제안
- 날짜: 2026-08-27 (예정)
- 관련 브랜치: `feat/sql-generation-scope`

## 결정 (한 줄)

> 착수 후 채운다.

## 맥락

LLM이 SQL 전체를 만들면 자유도는 높지만 검증 표면이 넓어진다.
원본 사례(카카오페이 MOZ팀)는 `SELECT *` 구조를 고정한 채 WHERE 조건만 LLM이 채우게 해
인젝션 위험을 줄였다.

## 검토한 대안

| 대안 | 판단 | 장점 | 단점 | 버린 이유 |
|---|---|---|---|---|
| LLM이 SQL 전체 생성 | | 자유도 최대 | 검증 표면이 가장 넓다 | |
| SELECT 구조 고정 + WHERE만 LLM | | 검증 표면이 좁아진다 | 표현 가능한 질의가 제한된다 | |
| LLM은 파라미터만 반환, 서버가 조립 | | 가장 안전 | 의도 종류만큼 조립 코드가 필요 | |
