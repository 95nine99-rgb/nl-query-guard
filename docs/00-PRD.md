# PRD — 거래내역 자연어 검색 백엔드 (Text2SQL 검증 및 안전 실행)

작성일 2026-08-24 · 기간 2026-08-24 ~ 08-29 (1주 · 하루 분량 2배)

## 배경 · 문제

사용자가 자연어로 거래내역을 묻는다. LLM은 자연어를 SQL로 그럴듯하게 바꾸지만,
그 SQL이 안전한지·권한 범위 안인지는 **모델이 판단할 수 없다**.
무엇을 실행시킬지 정하는 것은 백엔드의 몫이다. 이 프로젝트는 그 판단 레이어를 만든다.

## 목표

1. 규칙 기반으로 먼저 동작하는 파이프라인을 완성하고, **규칙이 깨지는 구간에만** LLM을 끼운다
2. 방어 없이 먼저 뚫려본 뒤 화이트리스트 파서로 막고, 악의적 SQL 12종 차단율을 측정한다
3. 의도 분류 신뢰도가 임계값 미만이면 실행하지 않고 사용자에게 되묻는다
4. 프롬프트를 바꿀 때마다 정확도 회귀를 CI가 자동으로 잡는다

## 비목표 — 하지 않을 것

- 모델 파인튜닝·자체 모델 학습. 이 프로젝트는 모델을 만드는 게 아니라 **통제하는 것**이다
- LangChain 등 프레임워크 도입. Spring Service 계층의 단계별 메서드로 대체한다
- 멀티턴 대화 컨텍스트 관리
- 차트·이미지 생성

## 성공 기준 — 이게 나와야 끝난 것

- [ ] 악의적 SQL 12종 차단율 표 (검증 레이어 적용 전/후). **뚫린 케이스가 있으면 숨기지 않고 기록**
- [ ] 의도 분류 정확도 30건 정답셋 기준 + CI에서 자동 측정되는 화면 1장
- [ ] LLM 3회 연속 실패 시 최종 동작이 정의돼 있고 로그로 증명됨
- [ ] ADR 2건 — SQL 생성 범위 · 검증 방식
- [ ] 게이트 질문 ①~④에 대한 답이 `06-retro.md`에 적혀 있을 것
- [ ] (여유 시) 복합 인덱스 적용 전/후 EXPLAIN 비교 — 2주 압축으로 우선순위 최하

## 범위 밖

검색 UI 고도화 · 다국어 질의 · 스트리밍 응답 · 실제 금융사 연동 · 관리자 대시보드

## 측정 환경 기록 규칙

확인 안 된 값은 비워두지 말고 **"미확인"**이라고 적는다.
